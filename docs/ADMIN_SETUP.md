# 개발 브랜치 관리자 인증 안내

이 문서는 **개발용 Apps Script 복사본**을 대상으로 한다. 학교에서 사용 중인 웹앱은 그대로 둔다.

## 변경된 보안 경계

- 학생 출석(`api_attend`)과 보충 접수(`api_makeup`)는 종전처럼 공개되며, 관리자 승인 절차는 아직 없다.
- 출석 관리·CSV·부원 수정·삭제·졸업·복귀 API는 서버에서 관리자 토큰을 확인한다.
- `setup_`, `findSchool_`, `recordAbsencesToday_`, `promoteYearly_`는 Apps Script의 private 함수로 변경됐다. 브라우저의 `google.script.run`에서 직접 호출할 수 없도록 한 것이다.
- 로그인 시 관리자 비밀번호 자체는 저장하지 않으며, 인증 성공 시 브라우저 메모리에서만 관리 토큰을 유지한다. 캐시 세션은 최대 4시간이고 중간에 사라질 수도 있다.
- `CacheService`의 실패 횟수는 모든 방문자에게 공유된다. 다수의 실패 로그인으로 일시적인 관리자 로그인 차단이 발생할 수 있다. 이 방식은 대규모 외부 공개 서비스의 완전한 인증·속도 제한 체계를 대신하지 않는다.

## 개발 환경에만 설정

1. 원본 Apps Script와 **다른 Script 프로젝트 및 다른 Google Sheet**를 사용한다.
2. `node scripts/create-admin-credential.mjs`를 로컬 PC에서 실행한다.
3. 터미널에 표시된 관리자 비밀번호를 안전한 곳에 별도로 보관한다.
4. 함께 출력된 `salt:sha256` 값만 Apps Script의 **프로젝트 설정 → 스크립트 속성 → `ADMIN_PASSWORD_HASH`**에 저장한다.
5. `NEIS_KEY`, `SHEET_ID` 등도 개발용으로 분리하며 GitHub에 커밋하지 않는다.
6. `clasp push` 전 `.clasp.json`이 **운영 프로젝트가 아닌 테스트 프로젝트**를 가리키는지 반드시 확인한다.
7. Apps Script 편집기에서 `setup_`와 `findSchool_`을 차례로 실행한다. `setup_`은 기존 이름의 결석 트리거도 제거한 뒤 새 트리거를 등록한다.
8. 개발 배포 URL에서 미로그인 관리 페이지 접근 거부, 로그인 성공/실패, 세션 만료, 로그아웃, 학생 출석을 확인한다.

`ADMIN_PASSWORD_HASH`를 설정하지 않았다면 관리자 기능은 로그인되지 않도록 설계되어 있다. 저장소에는 비밀번호와 해시를 모두 올리지 않는다.

## 검증

Node.js 20 이상에서 별도 npm 설치 없이 다음을 실행한다.

```powershell
node --test tests/*.test.cjs
```

이 테스트는 가상 데이터와 서비스 모의 객체를 사용한다. Google Apps Script 배포/권한 및 실제 Google Sheet의 작동까지 보장하지 않는다.

## 운영 승격 전 확인

- 학교 출석 데이터를 별도 백업한다.
- 기존 운영 웹앱 버전과 개발 배포 버전을 비교한다.
- 교내 접근 정책에 맞는 실제 인증 방식인지 책임자와 검토한다.
- 보충 승인과 이력 조회 문제가 해결되지 않았다는 점을 담당자에게 알린다.
- 안준표 저장소의 `main`에는 충분한 검증과 승인 없이 직접 반영하지 않는다.
